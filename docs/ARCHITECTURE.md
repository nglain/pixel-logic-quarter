# Устройство проекта

Игра работает в браузере без backend, сетевых запросов и внешних ресурсов. Разработка не требует framework или bundler: Python собирает готовый HTML из нескольких исходников.

## Владельцы поведения

| Файл | Ответственность |
|---|---|
| `src/quarter-source.html` | Карта, навигация, цепочки уровней, обучение, сейф, весы и переправа |
| `src/quarter-extra.js` | Башня, кувшины, мост и лампы |
| `src/quarter-hints.js` | Общая карта и поиск следующего полезного действия |
| `src/quarter-warehouse.js` | Три авторских склада, проверка ходов и поиск решения |
| `src/warehouse-style.css` | Поле склада и компоновка для мыши и touch |
| `src/pixel-cafe.html` | Правила автоматов, пробы, монеты и вывод по наблюдениям |
| `src/quarter-shell.html` | Автономный документ и адаптер сохранения в браузере |
| `scripts/build.py` | Подстановка исходников и адаптация кафе к общему сохранению |

`index.html` — сгенерированный результат. Он включён в Git для запуска одним файлом; исходники остаются единственным местом редактирования.

## Состояние и прогресс

Общее состояние хранит выбранное место, текущие положения головоломок и для каждого места пару `level / cleared`. Решение увеличивает число завершённых уровней. Кнопка следующего уровня проверяет, что текущий уже завершён; перезапуск не понижает накопленный прогресс.

Кафе использует собственное существующее состояние через тонкий адаптер. Сборка подключает его к общей коллекции: монеты и результаты проб не рассчитываются второй раз в оболочке.

В автономном браузере состояние хранится в `localStorage` под ключом `pixel-quarter-v1`; номер схемы внутри состояния — 2. При загрузке прежней схемы предусмотрена миграция. При расширении коллекции отсутствующие новые задачи добавляются, существующие не сбрасываются. Очистка браузерных данных удаляет локальный прогресс.

Подсветка обучения определяется из текущей позиции. У неё нет отдельного счётчика обязательных кликов. Ручная подсказка — состояние интерфейса: переход на другую задачу или уровень выключает её.

## Отображение

Canvas и CSS рисуют пиксельные декорации. Реальные области взаимодействия — нативные кнопки и списки с доступными подписями. Решение и расход ресурсов меняют игровое состояние; графика и анимации показывают уже принятый результат.

Общая карта перестраивается между 4×2 и 2×4. В сценах сохраняется компактное управление справа. Системная настройка reduced motion отключает движение там, где оно используется.

## Подсказки

Поиск использует положение задачи и наблюдения игрока. Короткий путь вычисляется для дисков, кувшинов и переправы; минимальная стоимость — для моста; линейная система над GF(2) — для ламп. Другие задачи фильтруют гипотезы по полученным ответам.

Подсказки помогают решить задачу и могут показать конкретный следующий ход. Это локальные алгоритмы, без LLM или API. Сохранение содержит состояние одиночной игры, включая секреты задач; оно не является защищённой системой результатов или соревнований.

## Проверки

`npm test` пересобирает игру и проходит сценарии в браузере. Проверки не включены в runtime игры. Отчёты и скриншоты создаются отдельно в игнорируемом `test-results/`.

## Иллюстрированное оглавление

`src/catalog.json` — единственный источник описаний, рубрик, статусов и порядка иконок для 30 задач. `scripts/build-catalog.py` выпускает автономный `catalog.html` и подробный `docs/CATALOG.md`. Интерфейс расположен в `src/catalog-shell.html`: слева оглавление по шести разделам, справа описание выбранной задачи; на узком экране выбор заменяется сгруппированным списком.

У девяти задач статус `playable` и ссылка на `index.html#<id>`. У остальных — `proposed`; кнопки запуска для них не создаются. Игра принимает только известные собственные идентификаторы сцен из fragment URL. Переход по ссылке не очищает сохранение. Навигация внутри игры обновляет fragment URL, поэтому перезагрузка восстанавливает текущую сцену, а не ранее открытую внешнюю ссылку.

`assets/catalog/puzzle-icons.png` — единый атлас ImageGen 6×5. Каждая иконка выбирается CSS-позицией; исходный PNG не меняется. При сборке он встраивается в автономный HTML. Промпт и описание происхождения находятся рядом с атласом. Индекс иконки уникален для каждой задачи.

`check-catalog.cjs` проходит все 30 описаний, проверяет статусы, структуру уровней, загрузку атласа, мобильный выбор, восстановление выбранного раздела по URL и переходы между оглавлением и существующей игрой.

## Склад и отмена действий

Склад использует статические определения поля в `quarter-warehouse.js`; в сохранение попадают только позиция игрока, ящики и счётчики. Решатель ищет последовательность толчков, вычисляя доступные подходы к ящикам. В ключе состояния используется отсортированное положение ящиков и достижимая область игрока; неподвижные углы без цели отсекаются. Все три уровня независимо проверены решателем и пройдены через UI. В первом два действия, во втором найден путь из 12 шагов, в третьем — из 24; это проверенные пути, не обещание минимума по шагам.

Единственный владелец отмены — общее поле `undo`. Запись содержит идентификатор игры, уровень и снимок её состояния до принятого действия. Снимок не содержит саму историю. Выбор предмета, неверный ход и операции без изменения состояния в историю не попадают. Кнопка ищет последнее действие текущей игры и уровня; другие игры не меняются.

Поддерживаются башня, кувшины, переправа, мост, лампы и склад. Отмена восстанавливает счётчики и позволяет выйти из проигрышной позиции; уже заработанное открытие уровней остаётся. Новый уровень и повтор очищают историю соответствующей игры. Кафе, сейф и весы не создают записи отмены: полученная информация остаётся оплаченной монетой, попыткой или взвешиванием.

История содержит не больше 24 действий на всю коллекцию. Перед сохранением старейшие записи также удаляются при приближении к лимиту host widget state; игровое состояние и достижения не выбрасываются. В браузерном прогоне сохранение с заполненной историей занимало около 5 КБ. При загрузке старых v2-сохранений добавляются только отсутствующий склад и пустая история; существующие положения сохраняются.

Вкладка «Склад» на узком экране показывает короткую строку показателей над полем. Внешние стены сжимаются, внутренние клетки сохраняют удобный размер для касания. Карта показывает все девять локаций сразу: 3×3 на широком экране, две колонки на узком.
